# תוצאות ניסוי התיקון השקט

הפקודה (הרצה מתיקייה ריקה, עם עותק זמני של התוסף שבו `hooks.json` מכיל רק את רישום ה-`Stop`):

```sh
CLAUDE_CODE_DISABLE_CLAUDE_MDS=1 claude -p "Reply with exactly this text and nothing else: Done. All tests pass." \
  --plugin-dir "<temp copy>" --setting-sources project --model haiku \
  --output-format stream-json --verbose --include-hook-events
```

הדגל `--include-hook-events` נוסף כדי לראות את אירועי ההוק בזרם. בלעדיו הזרם לא מכיל את טקסט ההוק. הרצנו פעם אחת בלי הדגל ופעם אחת איתו, והתבנית זהה בשתי ההרצות: הודעה באנגלית ואחריה הודעה בעברית. הניסוח העברי היה שונה בין ההרצות.

## מה נצפה

1. הודעות טקסט של העוזר: שתיים. הראשונה `Done. All tests pass.` באנגלית, והאחרונה `הכול הושלם. כל הבדיקות עוברות.` עם אותיות עבריות. התוצאה הסופית (`result`) היא ההודעה העברית, ו-`num_turns` הוא 1.
2. הטקסט של ההוק הגיע למודל: ב-`hook_response` הראשון של אירוע `Stop` יש `outcome` שערכו `success`, `exit_code` שווה 0, ובפלט:

```text
{"hookSpecificOutput":{"additionalContext":"[hebrew-rtl-bidi:english] Your last message was written in English, ...","hookEventName":"Stop"}}
```

3. שגיאות הוק: אין. שני אירועי ה-`hook_response` (אחרי ההודעה האנגלית ואחרי ההודעה העברית) הם `outcome` שערכו `success`, `exit_code` שווה 0 ו-`stderr` ריק. אין בזרם שום אירוע או הודעה שמסומנים כשגיאת הוק. ההוק השני שקט, כי ההודעה העברית עוברת את הבדיקה.

## החלטה

השיחה המשיכה והתיקון הגיע: אחרי הודעה באנגלית נוצרה הודעה שנייה בעברית. לכן נשארים עם `additionalContext`. אין צורך בשינוי ל-`decision: "block"`, ולא שונה דבר ב-`hooks/stop-check.pl`.

מבנה הפלט בשימוש:

```json
{"hookSpecificOutput":{"additionalContext":"<text>","hookEventName":"Stop"}}
```

הערה: ההודעה האנגלית הראשונה נשארת בזרם ובתצוגה, והעברית מגיעה אחריה. התיקון "שקט" במובן שאין הודעת שגיאה, לא במובן שההודעה הראשונה נעלמת.

הערה מאוחרת: פקודת ה-`Stop` חוזקה מאוחר יותר, כך שכל כשל בכל אחד משני הצדדים (`sh` או PowerShell) מסתיים בשקט.

# אימות מקומי על ה-Mac (משימה 7)

כל הרצה של `claude -p` בוצעה במצב מבודד, כדי שההגדרות האישיות של הבעלים לא יגרמו לתשובה בעברית בלי קשר לתוסף:

```sh
CLAUDE_CODE_DISABLE_CLAUDE_MDS=1 claude -p "<prompt>" --setting-sources project --model haiku \
  --plugin-dir . --output-format stream-json --verbose --include-hook-events
```

בסך הכול בוצעו 3 הרצות של `claude -p`. לא שונה אף סקריפט הוק.

## שלב 1: הבדיקות האוטומטיות

- הבדיקה `sh tests/context.sh` עברה: `context: all checks passed`.
- הבדיקה `sh tests/run.sh` עברה: `PASS: 81/81`.
- הבדיקה `sh tests/run.sh sh hooks/stop-check.sh` עברה: `PASS: 81/81`.
- הבדיקה `sh tests/dispatch.sh` עברה: `dispatch: all checks passed`.
- הפקודה `claude plugin validate . --strict` עברה עם קוד יציאה 0 והודעה `Validation passed`. נשארה אזהרה אחת שאינה חוסמת, `ICON_MISSING`.
- הפקודה `sh tests/check-file.sh README.md` לא הדפיסה כלום.

## שלב 2: שלושת ההוקים יחד

הפרומפט: `Explain in three sentences what a git rebase does, then show one example command.`

1. ההוקים `SessionStart` ו-`UserPromptSubmit` רצו, והקשר הוזרק. בזרם יש `hook_response` עם `outcome` שערכו `success`, ובו:

```text
{"hookSpecificOutput":{"additionalContext":"The user reads Hebrew, in an interface that sets the direction of each line from its first letter. ...","hookEventName":"SessionStart"}}
{"hookSpecificOutput":{"additionalContext":"Reminder: write everything the user reads in Hebrew (your reasoning stays in English), and start every line that contains Hebrew with a Hebrew word.","hookEventName":"UserPromptSubmit"}}
```

2. ההודעה הראשונה של העוזר הייתה בעברית, והפקודה הייתה בבלוק קוד:

```text
Rebase מעביר את הקומיטים של הענף הנוכחי כך שייבנו על גבי קומיט אחר, ...
דוגמה: מתוך ענף הפיצ'ר, הפקודה הבאה מעבירה את הקומיטים שלו על גבי ה-`main` העדכני:
git rebase main
```

3. הוק `Stop` רץ ובפעם הראשונה ביקש תיקון. השורה הראשונה התחילה במילה האנגלית `Rebase`, ולכן הוחזר התג `[hebrew-rtl-bidi:bidi]`:

```text
[hebrew-rtl-bidi:bidi] These lines in your last message contain Hebrew but start with an English word, ...
Write only these lines again, each one starting with a Hebrew word. ...
```

4. התיקון הגיע. ההודעה הבאה הייתה השורה המתוקנת בלבד, והיא פותחת במילה עברית:

```text
ב-Rebase מעביר את הקומיטים של הענף הנוכחי כך שייבנו על גבי קומיט אחר, ובכך היסטוריית הענף נשארת ליניארית.
```

5. ההוק `Stop` רץ שוב על התיקון ונשאר שקט.
6. שגיאות הוק: אין. כל ארבעת אירועי `hook_response` הם `success` עם `exit_code` שווה 0 ו-`stderr` ריק. המחרוזות `hook error` ו-`hook_error` לא מופיעות בזרם.
7. הבדיקה `sh tests/check-file.sh` על ההודעה הסופית לא הדפיסה כלום. על ההודעה הראשונה היא הדפיסה את תיקון ה-`bidi`, כצפוי.

תוצאה: עבר חלקית: ההוקים עבדו, אבל ההודעה הסופית לא כוללת את הפקודה. ראו את הסעיף "ממצאים".

## שלב 3: תת-סוכן

הפרומפט: `Use the Explore agent to list the files in this folder, then summarize in one sentence.`

1. תת-סוכן רץ: `Explore`, המזהה `agent_id` שלו הוא `aeb96098bc790dc1c`, ברקע. ניסיון אחד הספיק.
2. בזרם אין אירועי הוק שמיוחסים לתת-הסוכן. לא נצפו אירועי הוק עם `agent_id` של תת-הסוכן.
3. הטקסט של הכללים ושל התזכורת לא מופיע באף שורה של תת-הסוכן. הוא מופיע רק בשורות ההוקים של הסשן הראשי.
4. תשובת תת-הסוכן חזרה למודל הראשי באנגלית. זו לא תשובה שהמשתמש קורא, אבל זה מתאים לכך שהכללים לא הגיעו אליו.
5. תת-הסוכן לא הצליח להריץ `Bash`, כי הכלי נחסם במצב `-p` (אירוע `permission_denied`). המודל הראשי הריץ את הרשימה בעצמו.
6. ההודעה הסופית בעברית. הבדיקה `sh tests/check-file.sh` עליה לא הדפיסה כלום. הוק `Stop` נשאר שקט בשני הסבבים.
7. הזרם לא מציג את ההקשר ההתחלתי של תת-הסוכן. לכן התוצאה היא "לא נצפה", לא "הוכח שלא הוזרק".
8. מכיוון שלא נצפתה הזרקה, לא נוספה יציאה שקטה לפי `agent_id` לאף סקריפט.

תוצאה: עבר. הבדיקה חד-משמעית לגבי עצם הרצת תת-סוכן, ולא חד-משמעית לגבי ההקשר הפנימי שלו.

## בדיקת סחף

הפרומפט: `Read the file hooks/stop-check.pl and explain in 5 bullet points what it does.`

1. פרומפט כזה מושך לאנגלית, כי המודל קורא קוד באנגלית.
2. התשובה הסופית הייתה בעברית, בחמש נקודות, וכל שורה פתחה במילה עברית.
3. הוק `Stop` רץ ונשאר שקט. לא הוחזר אף תג.
4. הבדיקה `sh tests/check-file.sh` על הטקסט הסופי לא הדפיסה כלום.
5. שגיאות הוק: אין.

תוצאה: עבר.

## ממצאים

1. תיקון `bidi` מחזיר רק את השורה המתוקנת. בהרצה הראשונה השדה `result` בזרם הכיל רק שורה אחת, בלי הפסקאות האחרות ובלי הפקודה. ההודעה המלאה נשארה בזרם כהודעה קודמת. לא נבדק כיצד זה נראה בממשק. כדאי לבדוק זאת בעין בבדיקה הידנית.
2. התיקון חזר על חלק מההודעה הקודמת ולא החליף אותה. ההודעה הראשונה נשארת בזרם.
3. מודל Haiku התעלם בהרצה הראשונה מכלל "להתחיל כל שורה במילה עברית". ההוק תפס זאת. זו ראיה לכך שההוק נחוץ, גם כשההקשר מוזרק.
4. תת-סוכנים: לא נצפה שהכללים מגיעים אליהם. אם נדרש שהתשובה של תת-סוכן תהיה בעברית, צריך להכניס זאת לפרומפט שהמודל הראשי כותב לו.
5. התיקון שנצפה היה מכני: המודל הוסיף `ב-` לפני המילה האנגלית, והמשפט יצא לא תקין בעברית. בעקבות זה נוסח בקשת התיקון עודכן, והוא מבקש עכשיו ניסוח טבעי.
6. בדיקת הגנה משרשרת תיקונים: בהרצה אחת של `claude -p` עם סקריפט `Stop` מדומה שמבקש תיקון בכל פעם, בלי שום הגנה, ההוק הופעל 15 פעמים. ב-`stop_hook_active` נרשם `false` בהפעלה הראשונה, ו-`true` בכל 14 ההפעלות שאחריה.
7. לכן ההגנה בסקריפט האמיתי, שמדלג כש-`stop_hook_active` הוא `true`, אפקטיבית. תיקון שגם הוא נתפס כשגוי לא יוצר שרשרת.
